# Decision — Give the services section a clear visual anchor

Date: 2026-10-02
Decision: implemented

## Problem

The existing editorial index improved scanning over identical cards, but it still
read as a uniform list. The section lacked a clear first choice, a visual focal
point, and enough contrast to feel like a deliberate DN Tech moment on the page.

## Decision

- Keep the server-rendered semantic list and API fallback behavior.
- Present the first service as a navy featured panel and the remaining services as
  a lighter supporting rail.
- Use a flat, architectural composition: border, type scale, restrained orbit
  outlines, and oversized background wordmark instead of stock imagery or icons.
- Add a small entrance stagger and hover lift using only opacity/transform/color/
  shadow; disable motion under `prefers-reduced-motion`.
- Preserve the existing route JavaScript budget: no client component, animation
  library, or new image asset was added.

## Evidence and trade-offs

The design keeps the information-scent principles from the September decision:
the service name, description, and destination remain one semantic link. The new
featured-vs-supporting hierarchy adds visual differentiation without hiding the
catalog behind interaction. USWDS guidance supports using cards for a single
subject in a grid, while web.dev recommends limiting animation to compositor-safe
properties such as opacity and transform. MDN's reduced-motion guidance is applied
to avoid making the entrance effect a requirement for understanding the content.

## Adversarial review

- Counterargument: the featured first item may imply it is objectively the best
  service. Accepted; the badge says “Pilihan utama” as a visual entry point, not a
  sales claim, and the catalog remains fully visible.
- Counterargument: the oversized wordmark is decorative noise. Kept deliberately
  low-contrast and `aria-hidden`; it reinforces the section boundary without
  competing with service content.
- Counterargument: motion can hurt accessibility or mobile performance. The effect
  is one-shot CSS only, uses compositor-safe properties, and is disabled for
  reduced-motion users.
- Counterargument: longer API descriptions can make cards uneven. The grid lets
  the content size naturally; copy quality remains a separate CMS responsibility.
