# Plan — Mekari-inspired DN Tech design direction

Generated: 2026-09-27

## Decision

Adapt the information architecture and conversion patterns visible on Mekari's public ecosystem site for DN Tech, without copying Mekari's brand, illustrations, copy, or proprietary assets.

## Falsifiable hypotheses

1. A solution-led catalog grouped by business job will help visitors choose a DN Tech route faster than a generic service/product grid.
2. Repeated proof, status, scope, and next-step signals will improve B2B comprehension more than decorative visual effects.
3. A modular ecosystem narrative is useful for DN Tech only if each module links to a real product, service, case study, or contact path.

## Scope

- Public routes: home, services, products, proof/case studies, resources/blog, about, contact, FAQ, quiz, legal.
- Admin routes: shared shell, navigation, tables, forms, status surfaces.
- Preserve URLs, data contracts, hero imagery, SEO schema, and existing API behavior.

## Evidence strategy

- Primary: Mekari official homepage, product ecosystem, pricing, and resource pages.
- Local: current DN Tech route structure, existing design decisions, product/service data contracts.
- Method: compare information architecture, conversion surfaces, proof patterns, and segment fit; do not treat competitor claims as DN Tech claims.

## Risks and stop criteria

- Risk: copying a larger enterprise ecosystem makes DN Tech feel inflated. Stop if a module has no maintained proof or owner.
- Risk: too many solution categories increase choice overload. Keep the primary navigation to five or fewer jobs.
- Risk: visual similarity becomes brand confusion. Use DN Tech tokens, logo, copy, and imagery only.
