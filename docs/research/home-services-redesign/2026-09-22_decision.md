# Decision — Replace Repetitive Service Cards with an Editorial Index

Date: 2026-09-22
Decision: implemented

## Problem

The old section presented every service as an identical rounded card with a decorative number, two-line truncation, and the same “Pelajari lebih lanjut” treatment. That made four different engagements feel interchangeable and produced an unfinished final row at common desktop widths.

## Decision

- Use a two-part desktop composition: decision-oriented introduction on the left, service index on the right.
- Collapse to one linear reading order on mobile.
- Keep full API descriptions instead of clipping them.
- Make each linked row one large semantic navigation target.
- Use borders, whitespace, type scale, and existing DN Tech tokens; no gradients, glass, shadows, or decorative service icons.
- Preserve API fallback behavior and add no client-side JavaScript.

## Hypothesis results

1. Equal cards weaken differentiation: supported by the information-scent and hierarchy evidence, although cards remain valid for other jobs.
2. Outcome framing improves scanning: supported directionally; the section heading now starts from the visitor's decision and the full descriptions stay visible.
3. Restrained editorial composition can carry identity: supported in visual review at 1440 px and 390 px without adding imagery or runtime weight.

## Adversarial review

- Counterargument: cards are familiar and can offer large targets. Accepted; the new rows retain large targets and strong grouping without card decoration.
- Counterargument: the left/right layout creates empty space. On desktop this space establishes hierarchy and balances a long service list; on mobile the layout becomes linear.
- Counterargument: removing icons can reduce quick recognition. Generic icons would not add reliable meaning to custom software categories; service names remain the stronger cue.
- Counterargument: visual redesign cannot repair weak catalog copy. Correct. API descriptions remain a separate content-quality dependency and should be reviewed using lead language.
